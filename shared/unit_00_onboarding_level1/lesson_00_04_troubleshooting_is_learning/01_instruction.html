0.4 — Troubleshooting Is Learning

What you'll take away:
  • I can explain why something not working is a normal, expected part of building things, not a sign I did something wrong.
  • I can use a simple troubleshooting process instead of guessing randomly or giving up.

At some point this year, something you build is going to break. Your code will throw an error. A layout will look wrong in the browser. A Unity scene won't run the way you expected. This isn't a maybe, it's a certainty, and it's true for every single person in this class, including the adults who do this professionally.

Reframe: This Is Part of the Job

Professional software developers, web developers, and game developers spend a large part of their actual working time fixing things that don't work yet. It's not a side effect of the job, it's a core part of it. Getting comfortable with something being broken, and calmly working out why, is one of the most valuable skills this whole class is building.

A Simple Process, Not a Guessing Game

When something breaks, it's tempting to change random things until it works. That sometimes works by accident, but it teaches you nothing and often creates new problems. Try this instead.

1Notice exactly what happened

What did you expect to happen? What actually happened instead? Read any error message carefully, word for word, instead of skimming past it. The message is usually telling you something specific and true, not just "it's broken."

2Find what changed

If it worked a minute ago and doesn't now, what did you just change? That's usually where the problem is. If it never worked, look at the most recent piece you added or edited.

3Make one change at a time

Fix one thing, then check whether the problem is gone before fixing anything else. If you change five things at once and it works, you won't know which change actually mattered, and you won't have learned anything you can use next time.

4Ask for help the right way

If you're stuck after trying the steps above, that's exactly when to ask for help, not a sign you should have figured it out alone. The next lesson (Getting Unstuck) covers exactly how to do this well.

What This Looks Like in Each Pathway

The specific symptom looks different depending on what you're building, but the process above works the same way for all of them:

  • In Python, a bug usually shows up as an error message called a traceback, or output that isn't what you expected.
  • In web development, a bug might be a page that looks wrong in the browser, a button that doesn't do anything, or a JavaScript error in the browser's console.
  • In Unity, a bug might be a game object that doesn't move, a script that throws an error in the console, or a scene that doesn't behave the way you designed it.

Different symptoms, same underlying skill.
