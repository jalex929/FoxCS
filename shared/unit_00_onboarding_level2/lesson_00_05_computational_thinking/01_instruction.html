0.5 — Introduction to Computational Thinking

What you'll take away:
  • I can name and describe the four core parts of computational thinking.
  • I can spot at least one of them happening in a problem I already know how to solve.

Computational thinking isn't the same thing as coding. It's the thinking that happens before and during coding (or building a web page, or designing a game system). It's how you break a big, messy problem into something you can actually solve, one piece at a time. You already do a version of this in everyday life. This class just gives it names and makes it deliberate.

The Four Parts

Decomposition
Breaking a big problem into smaller, more manageable pieces.
Example: "Build a website" is huge. "Build the header, then the navigation, then the main content" is a set of problems you can actually start on.
Pattern recognition
Noticing similarities between a new problem and something you've seen before.
Example: Once you've fixed one "my button doesn't respond to clicks" bug, you'll recognize the shape of that problem the next time it shows up somewhere else.
Abstraction
Focusing on the details that actually matter for the problem you're solving, and ignoring the ones that don't.
Example: When you use a function someone else wrote, you don't need to know exactly how it works inside, just what it needs from you and what it gives back.
Algorithmic thinking
Describing a solution as a clear, ordered series of steps.
Example: A recipe is an algorithm. So is a set of directions to a friend's house. So is the logic behind almost anything you'll build this year.
Quick Check
You're planning a birthday party and you write a list: decorations, food, music, invitations, then handle each one separately. Which part of computational thinking is this closest to?

Why This Matters Before You've Written Any Code

Every project you build this year, whether it's a Python program, a web page, or a Unity game, is really a large problem made out of many small ones. Students who struggle the most usually aren't struggling with syntax, they're trying to solve the whole big problem at once instead of breaking it down first.

When you get stuck later this year, one of the first useful questions to ask yourself is: what's the smallest piece of this I could try to solve first? That question is decomposition, and it's often the fastest way out of feeling stuck.
