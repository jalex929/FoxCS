# Privacy and data boundaries

## Principle: privacy by separation

A student's real identity lives in exactly one place: a private roster controlled by the teacher. Every other system works on pseudonymous IDs only. Moodle usernames are pre-generated pseudonymous IDs, so submissions, telemetry, grading reports, and anything an AI tool sees are keyed by that ID from the start.

## System by system

| System | Receives | Never receives |
|---|---|---|
| Moodle | Pseudonymous account, course content, submissions, approved grades and feedback | Real name tied to grading logic |
| Deterministic grader | Pseudonymous ID, submission files | Name, school ID, email, guardian information |
| AI-assisted review | Pseudonymous ID, submission files, rubric, pseudonymous history | Same as above |
| Teacher spreadsheet | Two strictly separate tabs: a private roster (ID to name) and a results tab (pseudonymous only) | The two tabs are never merged |

## Release Gate

Nothing generated by AI (score, feedback, XP, next-step recommendation, guardian update draft) reaches a student or guardian without explicit teacher approval. No exceptions for high-confidence results.

## Interaction telemetry

The telemetry plugin records how students move through a lesson: quiz checks, drill attempts, hints, practice-ladder transitions, save and resume state. It contains no identity information by construction and falls under the same boundaries as submissions. Behavioral data is a different sensitivity category than submitted work even without identity, so it is treated as in scope for any privacy review, not exempt from it.

## Limits I am explicit about

- **Pseudonyms are not anonymity.** Free-text answers and code comments can contain identifying details. Pseudonymous IDs reduce exposure. They do not make student work safe to publish or to send to any service without review.
- **Compliance is a review, not a design property.** The separation design supports student-privacy obligations but does not by itself establish compliance with district policy or state law. That confirmation belongs to the district's data privacy process.
- **Retention is a decision, not a default.** How long submissions and reports are kept needs an explicit policy before scale, not after.

## What this repository contains

Only synthetic data. Every student in `grader/sample-submissions/` and `evals/cases/` is invented. `tools/check_showcase_clean.py` fails CI if a real pseudonymous ID format, a district contact, live infrastructure, a credential, or licensed course material appears anywhere in the repository.
