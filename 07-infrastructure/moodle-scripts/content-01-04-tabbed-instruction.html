What Does print() Do?

print() is a built-in Python function that displays output to the screen. When Python runs print("Hello"), it takes the text inside the quotes (a string: any sequence of characters wrapped in quotes) and writes it out where you can see it.

print() is your program's only way of talking to whoever is running it. Without it, a program could do all kinds of correct work internally and whoever's watching the screen would never know.

Anatomy of a print() Statement

Every print() statement has three required parts: the word print (always lowercase), parentheses (), and a string inside quotes.

print("Hello, World!")

If any part is missing or misspelled, Python won't run the line at all. It raises a SyntaxError before your program even starts.

Reading it line by line: Python sees print and knows to call the print function → sees ( and starts reading what's being passed in → sees the string in quotes → sees ) and knows the input is complete → displays the text.

Two Mistakes Everyone Makes at First

Forgetting to close the quote
print("Hello, Python!)

Python shows SyntaxError: EOL while scanning string literal. EOL means "End Of Line" -- Python reached the end of the line while still looking for the closing quote. The fix: print("Hello, Python!").

Missing parentheses
print "Hello"

Python 3 shows SyntaxError: Missing parentheses in call to 'print'. That's Python 2 style (no parentheses) -- in Python 3, print is a function, and every function call needs parentheses. The fix: print("Hello").

Neither of these means you did something wrong as a learner. They mean Python found a genuine grammar rule it needs followed exactly. Reading the error message is how you find out which rule.

Game Connection

print() is your program's simplest form of feedback to whoever is using it, the same role a game's UI plays when it tells a player "Enemy defeated!" or "Not enough gold."

A program that prints 1 when something fails and 0 when it succeeds is technically giving output, but it's terrible output -- nobody can tell what happened without memorizing a code. Specific, readable output is better: "Not enough gold. You need 20 more." tells a player exactly what happened and what to do next. "Error 402" or nothing at all tells them nothing.
