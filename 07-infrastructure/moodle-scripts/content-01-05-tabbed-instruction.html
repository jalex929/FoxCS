Leaving Notes for Humans, Not for Python

A comment is a line (or part of a line) that Python completely ignores when it runs your program. In Python, anything after a # on a line is a comment:

# This program greets the player
print("Hello!")
# End of program

Run this, and you'll see only Hello!. Both comment lines produce no output at all, because Python skips them entirely. They're not for the computer. They're for you, and for anyone else who reads your code later.

Why Bother, If Python Ignores Them Anyway?

Because code gets hard to remember. Code that makes perfect sense while you're writing it can look like a mystery a week later, or to a classmate seeing it for the first time. A comment that explains why a piece of code exists (not just what it does, which the code already shows) saves real time and confusion later.

Weak Comments Just Repeat the Code

# print the score
print(score)

That adds nothing you couldn't already read. A strong comment adds something the code doesn't already say:

# show the score after every round, per the game design doc
print(score)
Real-World Example: Sticky notes on a recipe card.

Imagine a recipe card with a sticky note that says "double this for a crowd" next to a step. The sticky note isn't part of the recipe itself, a cook could ignore it and still make the dish. But it adds real, useful context for whoever reads the card next. That's exactly what a comment does for code.

Comments Can Also "Turn Off" a Line Temporarily

Putting a # in front of a line of actual code stops that line from running, without deleting it. This is called commenting out a line, and it's a normal part of testing and debugging:

# Display the welcome message
print("Welcome")
# Display the instructions
# print("Press start")
print("Ready to go")

This displays only Welcome and Ready to go. The commented-out print("Press start") never runs, even though it's valid Python code sitting right there in the file.

Game Connection

Professional game studios have whole teams of programmers working on the same codebase at once. A comment like # TODO: rebalance this enemy's health before playtesting or # this check exists because level 3 had a bug where the timer went negative is exactly how one programmer leaves useful context for the next person who opens the file. Sometimes that "next person" is the same programmer, six months later, who has genuinely forgotten why they wrote something a certain way.
