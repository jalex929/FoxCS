# Lesson Quality Standards

See `content-authoring-standards.md` for the actual DOK-level rubric, universal design rules, and documentation standards referenced below — this file is the checklist; that file is the reference you write against.

Every lesson should:

- Have a clear purpose and state what students will learn and what they should already know.
- Use language appropriate for high-school learners and adults — avoid assuming all learners identify primarily as "students."
- Break complex ideas into manageable steps without unnecessary cognitive overload.
- Include multiple examples, and practice before independent assessment.
- Include meaningful opportunities to make mistakes safely, and explain common errors without shame.
- Support multiple valid problem-solving approaches — never treat one sample solution as the only correct one.
- Include a stuck pathway and an optional challenge pathway.
- Include reflection or explanation opportunities, and treat them as real evidence of learning (see `lesson-schema.md`'s `skip_check_required`), not a box to check.
- Include explicit success criteria and accurate grading criteria.
- Include accessibility considerations (see `content-authoring-standards.md`'s Universal Design section).
- Include sufficient evidence for both automated and human grading — a rubric with no supporting evidence trail isn't gradable at the confidence this system needs.
- Connect misconceptions to specific review resources (a misconception code with nowhere to send the student is a dead end).
- Clearly explain what the student should do next, on both the Moodle side (what to do in VS Code) and after VS Code (submission, reflection, what's next).
- Deliberately span more than one DOK level, using both surfaces (see `lesson-schema.md` and `content-authoring-standards.md`'s DOK rubric) rather than concentrating all challenge in one place.
