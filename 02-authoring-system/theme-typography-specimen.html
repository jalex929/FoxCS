Waypoint Theme + Typography Specimen

A real, working preview of the 4 themes in logos/waypoint_theme_typography_style_guide_full.md. This is a reference/documentation tool, not lesson content.

Typography

Heading font changes per theme (Atkinson Hyperlegible for Light/Dark, Nunito Sans for Natural, JetBrains Mono for Synthwave). Updated 2026-08-10: body text no longer has to be Atkinson Hyperlegible in every theme either — Light/Dark keep it (their whole brief is familiar and low-distraction), but Natural now reads in Lora and Synthwave in Sora, both real text faces built for reading at length, not display/script faces. The guide's original Section 4 principle still holds: personality comes from a considered choice of legible faces, never from making body text harder to read.

Waypoint students may spend long stretches reading directions, feedback, and vocabulary — this paragraph is set at the guide's preferred instructional size (17–18px) and line height (1.55–1.7), and this sentence is kept inside the 60–75 character line-length range the guide recommends for comfortable reading.

def greet(name):
    print("Hello, " + name + "!")

greet("Waypoint")

Code always uses JetBrains Mono — in Synthwave it's also the heading font, so size/surface/spacing carry the distinction between "this is a heading" and "this is code," not typeface alone (guide Section 21).

Live on this page right now, behind everything you're reading — Natural gets a fine parchment/paper grain, Synthwave gets a quiet line grid, Light/Dark get neither. Both are generated (SVG fractal noise for the grain, a repeating CSS gradient for the grid), not a tiled photo, so there's no visible repeat seam and nothing to interfere with text. Semantic Feedback

✓Success — the concept clicked. Green stays green across every theme; it's the one semantic color the guide treats as safe to keep intuitive.
!Warning — worth a second look, not necessarily wrong.
×Error / incorrect — never red in FoxCS. Red is reserved specifically for academic-integrity flags (see design-system.md's Tone Note); general incorrect-answer feedback always uses a warm, non-alarming tone instead.
