# GMetrix / Certiport "Unity Certified User: Programmer" — Real Exam Objectives

**Source:** Jay's own licensed GMetrix account, Unity Certified User: Programmer Study Guide, read directly 2026-08-31 (`https://www.gmetrix.net/program/191/study-guide`). Real, complete 18-topic objective list. Per Jay's correction 2026-08-31: this certification is offered through Certiport/GMetrix (the "Unity Certified User" program), not administered separately by Unity Technologies directly.

Passing threshold per topic: **80% proficiency required** in each of the 18 topics below. Unlike the other Certiport exams, these objectives are written as scenario-based "given X, do Y" statements rather than short numbered skill names — reproduced verbatim below.

1. Given an example of a debug log message, create the code that created the log message.
2. Given a code clip and its associated error message(s), determine which object(s) is(are) null.
3. Given a specific programming task requiring the use of a particular class in the API, determine the appropriate method and/or properties, arguments, or other syntax to use.
4. Indicate when and how to initialize and use variables.
5. Given a list of keywords and syntax elements, construct a viable Function declaration.
6. Given a code clip and a description of its desired result, identify the appropriate function to control or trigger a state.
7. Given a scenario where a specific type of input is required and the building blocks needed are provided, construct the necessary input listener.
8. Demonstrate when and/or how to use the various logic and flow control operators used in C# and Unity.
9. Given a scenario, identify appropriate actions to take when a UI element reports a change.
10. Given a scenario about the need to manage an event function, determine the appropriate action to take.
11. Given a code clip that produces an error because of a variable whose data type is declared incorrectly, identify the error.
12. Given a code clip that produces an error because a function or variable is declared or used incorrectly (public/private mismatch), identify the error.
13. Given a code clip containing a class definition, distinguish whether the class is an ECS class or some other type of class.
14. Given a set of code clips, recognize the clip which uses naming conventions that observe Unity naming standards.
15. Given a code clip (or a set of code clips), recognize the comments which accurately describe what the code is doing.
16. Describe the purpose, features, and functions of the various Unity IDE windows.
17. Demonstrate how to change the default scripting IDE.
18. Given a scenario which includes the following, then create a functional state machine.

## What this means for FoxCS's Game Design/Unity pathway

This is a real C# programming exam grounded in Unity's specific API/IDE conventions, not general C# alone — it explicitly tests Unity naming conventions, the Unity IDE itself, event functions, UI event handling, and (notably) **ECS (Entity Component System) class recognition** (#13), a more advanced/modern Unity architecture concept not yet reflected anywhere in `course-plan.md`. Debugging and error-identification from code clips is a recurring pattern across roughly a third of the objectives (#1, #2, #11, #12, #15) — worth building real debugging-from-a-code-clip practice into the pathway early and often, not just at a dedicated "debugging unit."
