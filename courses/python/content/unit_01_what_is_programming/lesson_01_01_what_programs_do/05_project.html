Unit Project

1.1.5a Project Instructions: Design a Program

A short applied task before the mastery check. You haven't learned real Python syntax yet (that starts in 01.3), so this project applies this lesson's big idea directly: a program is an exact, ordered set of instructions. You'll write that set of instructions yourself, in plain English, for a system of your choice.

The Task

Pick one real-world system that runs on a program, other than the vending machine from this lesson's instruction page (an ATM, a microwave, a traffic light, an alarm clock, or a simple game mechanic like a jump button are all good choices). Write out the exact, numbered instructions a computer would need to follow to run it, the same way the vending machine example broke its behavior into exact steps.

What This Could Look Like

Here's a similar instruction list for the vending machine from the lesson, just to show the shape of what you're building. Yours needs to be for a different system, and doesn't have to look anything like this one.

1. Wait for money to be inserted.
2. Check how much money has been inserted so far.
3. If the amount inserted is less than the item's price, do not release the item.
4. If the amount inserted is enough, release the item.
5. If the amount inserted is enough, give back any extra change.

Hint 1: Start by picking your system, then just describe what it does out loud, step by step, the way you'd explain it to a friend. Each separate thing it does or checks is one instruction.

Hint 2: Every system in the suggested list has at least one moment where it has to check something and behave differently depending on the answer, like the vending machine checking whether enough money was inserted. Find that moment in your system first, then work out the steps before and after it.

Hint 3: A shape to fill in, not a solution. Using an alarm clock as the example system this time (pick your own, don't just copy this one):

1. Wait for the alarm time to be reached.
2. Check whether the alarm is turned on.
3. If the alarm is on, [what happens?]
4. If the alarm is off, [what happens?]
5. [one more step of your choosing]

Game Connection

What you're doing here is exactly what game designers call a "design document" or "spec" before any code gets written: describing precisely what the system should do, step by step, so that whoever writes the actual code (possibly you, later this year) has an exact plan to follow instead of guessing.
