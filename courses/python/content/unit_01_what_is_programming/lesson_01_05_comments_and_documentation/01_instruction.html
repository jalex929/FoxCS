01.5: Comments and Documentation

Learning objectives:
  • I can predict which lines of a program run, when some lines are comments.
  • I can write a comment that explains why a line of code exists, not just what it does.
Language objective:
  • I can explain the difference between code and a comment using the terms comment and documentation.

Leaving Notes for Humans, Not for Python

A comment is a line (or part of a line) that Python completely ignores when it runs your program. In Python, anything after a # on a line is a comment:

# This program greets the player
print("Hello!")
# End of program

Run this, and you'll see only Hello!. Both comment lines produce no output at all, because Python skips them entirely. They're not for the computer. They're for you, and for anyone else who reads your code later.

Why Bother, If Python Ignores Them Anyway?

Because code gets hard to remember. Code that makes perfect sense while you're writing it can look like a mystery a week later. Or to a classmate seeing it for the first time. A comment that explains *why* a piece of code exists (not just *what* it does, which the code already shows) saves real time and confusion later.

A weak comment just repeats the code: # print the score above print(score) adds nothing you couldn't already read. A strong comment adds something the code doesn't already say: # show the score after every round, per the game design doc tells you why this line exists.

Game connection: Professional game studios have whole teams of programmers working on the same codebase at once. A comment like # TODO: rebalance this enemy's health before playtesting or # this check exists because level 3 had a bug where the timer went negative is exactly how one programmer leaves useful context for the next person who opens the file. Sometimes that "next person" is the same programmer, six months later, who has genuinely forgotten why they wrote something a certain way.

Comments Can Also "Turn Off" a Line Temporarily

Putting a # in front of a line of actual code stops that line from running, without deleting it. This is called commenting out a line, and it's a normal part of testing and debugging:

# Display the welcome message
print("Welcome")
# Display the instructions
# print("Press start")
print("Ready to go")

This displays only Welcome and Ready to go. The commented-out print("Press start") never runs, even though it's valid Python code sitting right there in the file.

Key Terms

comment
A line (or part of a line) starting with # that Python ignores when running the program.
documentation
Written explanation of what code does and why. Comments are the simplest form of it.
commenting out
Disabling a line of real code temporarily by putting a # in front of it, without deleting it.
