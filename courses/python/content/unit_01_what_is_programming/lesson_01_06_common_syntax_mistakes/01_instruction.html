01.6: Common Syntax Mistakes

Learning objectives:
  • I can identify and fix common early Python mistakes.
  • I can explain the difference between a SyntaxError and a NameError.
Language objective:
  • I can explain what went wrong in broken code using the terms SyntaxError, NameError, and syntax.

This Lesson Is a Review, on Purpose

You've already met most of these mistakes in Lessons 01.3-01.5, one at a time. This lesson is where you get fast at recognizing all of them at once, in code you didn't write yourself. Which is closer to what real debugging actually feels like.

The Big Four, Side by Side

MistakeBroken exampleWhat Python saysFix
Missing closing quoteprint("Hello)SyntaxError: EOL while scanning string literalAdd the missing closing quote.
Missing parenthesesprint "Hello"SyntaxError: Missing parentheses in call to 'print'Wrap the argument in ().
Wrong capitalizationPrint("Hi")NameError: name 'Print' is not definedprint must be all lowercase. Python is case-sensitive.
Missing quotes entirelyprint(Hello)NameError: name 'Hello' is not definedWrap the text in quotes so Python treats it as a string, not a variable name.

Notice two of these say NameError, not SyntaxError. That's worth understanding, not just memorizing. Print with a capital letter, or Hello with no quotes, both look to Python like the name of a variable that doesn't exist yet, not like a mistyped keyword or a piece of text. Python isn't confused about grammar in these two cases. It's looking for something by that exact name and not finding it.

How to Actually Debug One of These

  1. Read the error message's last line first. It names the actual problem.
  2. Find the line number Python points to.
  3. Compare that line, character by character, against the rules: lowercase print, matching parentheses, matching quotes.
  4. Fix one thing, run again. If a new error appears, that's progress, not failure. You fixed the first problem and uncovered the next one.
Game connection: This is your first real taste of what Unit 13 will call "playtesting your own code" and what real game studios call QA (quality assurance). The deliberate, systematic process of finding what's broken before it reaches a player. Right now the "player" is just Python's error message, and the "bug" is a missing character. The habit you're building here (read the message, find the line, check it against the rule, fix one thing at a time) is the exact same habit a professional QA process runs at a much larger scale.

Key Terms

SyntaxError
An error Python raises when code breaks its grammar rules.
EOL
"End Of Line". Appears in error messages when Python reaches the end of a line unexpectedly, often from a missing closing quote.
syntax
The grammar rules for writing valid code.
parenthesis
The ( or ) symbol used to call a function in Python.
