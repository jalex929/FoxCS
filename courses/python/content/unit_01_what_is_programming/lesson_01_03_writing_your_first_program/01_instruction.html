01.3: Writing Your First Program

Learning objectives:
  • I can write and run a Python file in VS Code.
  • I can predict what a short program will display, based on the order of its statements.
Language objective:
  • I can explain why Python's output follows a specific order using the terms sequential and execute.

Your First Real Program

Everything up to now has been ideas. This lesson, you write an actual program and run it. Open 2_examples/example_01.py in VS Code, and you'll see something like this:

print("Hello, Python!")
print("This is my first program.")

Run it (VS Code's Run button, or whatever your teacher showed you in Unit 00). You should see both lines of text appear, in the same order they're written. That's not a coincidence. It's the single most important rule about how Python runs your code.

Python Runs Top to Bottom, One Line at a Time

Python reads your file starting at the very first line and works its way down, running one instruction, then the next, then the next. It never skips ahead, never runs two lines at the exact same moment, and never runs them out of order. If a program has five lines, the fifth line's effect is always the last thing that happens, because Python didn't get to it until it finished the first four.

This is called running sequentially. In a fixed sequence, one step at a time. It's the same idea from 01.1's recipe comparison: a recipe's steps happen in the order they're written, not in whatever order looks convenient in the moment.

Predicting Output Before You Run It

Reading code and predicting what it will display before you run it, then checking whether you were right, is a genuinely useful skill you'll use all year. Try it here:

print("Line 1")
print("Line 2")

Before you scroll on: what will this display, and in what order? (It displays Line 1 then Line 2, each on its own line, because Python ran the first print() completely before starting the second one.)

Game connection: "Runs top to bottom, one instruction at a time" is true of game code too. Before a game can respond to your input at all, it typically runs setup code first: loading the level, placing objects in their starting positions, initializing the score to zero. That setup code runs in order, once, before anything else happens, using the same sequential rule you just used to predict Line 1 then Line 2. (What happens after setup, the part that repeats over and over while you play, is the "game loop" you'll meet properly in Unit 06.)

Key Terms

execute
To run a line of code. To carry out its instruction.
sequential
In a specific order, one step at a time.
output
Text or data that appears on the screen when code runs.
statement
A single instruction in a Python program.
