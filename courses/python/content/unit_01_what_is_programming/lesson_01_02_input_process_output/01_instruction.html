Unit Project

1.2.1 — Instruction: Input-Process-Output

Learning objectives:
  • I can describe the Input-Process-Output (IPO) model.
  • I can identify the input, process, and output stages in a real, familiar system.
Language objective:
  • I can explain how a system works using the terms input, process, and output.

Every Interactive Program Follows the Same Pattern

Almost everything a program does can be broken into three stages:

INPUT
receives data from outside
→
PROCESS
transforms or evaluates it
→
OUTPUT
delivers the result

Input is anything the program receives from outside itself. Something a person types, a button press, a sensor reading. Process is the work the program does with that input. Calculating, comparing, deciding. Output is what the program delivers back. Text on a screen, a sound, a printed receipt.

Here's a concrete example: a quiz app shows you a question (this already happened before your turn), you type an answer (input), the app checks your answer against the correct one (process), and it shows "Correct!" or "Try again." (output). Notice that the "work" (the actual checking) is the process stage. The question and the message are input and output. They're not the thinking part.

Quick Check
In the quiz app example, checking whether the typed answer matches the correct one is the ___ stage.
Real-World Example
An automatic hand dryer is Input-Process-Output too

A sensor detects that hands are underneath it (input). The dryer's circuit decides the fan should turn on because it detected something in range (process). The fan runs and warm air blows out (output). No person is deciding anything in the moment. The three stages just happen, one after another, exactly the way they were built to.

Quick Check
A hand dryer's fan turning on and blowing air is which stage?
Game Connection

This is the exact pattern behind every interactive game, not just quiz apps. You press a button (input) → the game figures out what that means given the current situation, like whether you're allowed to jump right now (process) → the game updates the screen to show your character jumping (output). A game that never took input would just be a video playing on a loop. A game that never processed anything would just repeat the same output no matter what you did. It's the combination of all three, running over and over, that makes something feel interactive. You'll see exactly how "running over and over" works when we get to loops in Unit 06. For now, just the three stages.

Key Terms

input
Data a program receives from outside itself.
Example: Typing your name into a sign-in kiosk. Pressing a button on a game controller.
process
The work a program does with input. Calculating, comparing, deciding.
Example: Checking a typed answer against the correct one. Deciding whether a character is allowed to jump right now.
output
What a program delivers back as a result. Text, sound, an image, anything the outside world can perceive.
Example: A kiosk displaying "Welcome, [name]!" A character jumping on screen.
system
Any program or machine considered as a whole, made of input/process/output working together.
Example: A quiz app, a vending machine, and a hand dryer are all systems, even though they look nothing alike.
