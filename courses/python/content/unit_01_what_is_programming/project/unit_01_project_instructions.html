Unit Project

Unit 01 Project: Interactive Greeting

A heads-up before you start: real, live interactivity, where your program actually reads what a player types, doesn't get taught until Unit 03. This project is a preview: you'll write out, entirely in print() statements, what an interactive greeting exchange would look like, as if the player had already told you their name and one thing about themselves. You're not faking anything or doing it "wrong" by not using real input. You literally don't have the tool for that yet, and that's fine. You'll build the real version once you learn input().

The Scenario

Imagine a simple program that greets whoever is using it by name, asks how they're feeling, and responds differently depending on what they'd say. You're going to write the script for that exchange. Every line either side would say. Using only what you've learned in Unit 01: print(), comments, and running your code in the right order.

Requirements

  • At least 6 print() statements, in an order that reads like a real back-and-forth greeting exchange.
  • At least one comment that explains what a section of the program is doing and why. Not just restating the line below it (see 01.5 if you need a refresher on weak vs. strong comments).
  • No syntax errors. Run your file and fix anything Python flags before you submit (see 01.6).
  • The greeting should feel personalized, not generic. Invent a specific name and a specific detail for the player in your script, the same way a real game greets a specific player rather than printing "Hello, player" to everyone.
Game connection: Every game with a character-creation or save-file screen does some version of this. Greeting a specific player by name, welcoming them back, referencing something about their save. Right now you're writing that experience by hand, one line at a time, exactly in the order it should appear. Once you have real input (Unit 03) and variables (Unit 02) in your toolkit, you'll be able to make the "name" and "detail" actually come from whoever's playing, instead of writing them in yourself. But the print-statement skill of shaping *what the player reads* doesn't go away once that happens. It's the same skill either way.

Example Shape (Don't Copy. Write Your Own)

# Greet the player by name
print("Welcome, Jordan!")
# Acknowledge something specific about them, not a generic greeting
print("I heard you just beat your high score in the last game you played.")
print("How are you feeling today?")
# This line stands in for where real input would eventually go
print("(imagine the player answers: pretty good!)")
print("Glad to hear it. Let's get started.")

Submitting

No renaming needed. Just save your work in unit_01_project.py, in this same folder, and submit the whole Unit 01 folder as instructed. Your teacher's own script takes care of matching your submission to you after you turn it in.

Handoff to VS Code: Open unit_01_project.py in this same folder (project/) and build your greeting exchange directly in it, below the comment already there.

Don't forget to save your file (Ctrl+S) before you're done.
