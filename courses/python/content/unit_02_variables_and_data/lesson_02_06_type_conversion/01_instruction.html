2.6 Type Conversion: Instruction

Why This Matters

Conversion changes how Python should interpret a value. Look at "12". To a person, that looks like a number. To Python, it's text until you explicitly convert it. Every value coming from input() is text, always, even if the student typed digits -- which is exactly why this comes up constantly once programs start asking users for numbers.

type() and Reading Its Output

You already have type() from earlier lessons -- 2.6 is about actually doing something with what it tells you. Run type("12") and Python answers <class 'str'>. That output format is always the same shape: <class '...'> with the type's name inside the quotes. Once you can read that output, the next question is what to do about it.

The Three Conversion Functions

Three functions change a value's type on purpose:

  • str(x) -- converts x to text. str(12) becomes "12".
  • int(x) -- converts x to a whole number. int("12") becomes 12.
  • float(x) -- converts x to a decimal number. float("12") becomes 12.0.

Picking the right one depends entirely on what the value needs to do next. Going into a math calculation? You need int() or float(). Going into a print() alongside other text with +? You need str().

Predicting Valid and Invalid Conversions

Not every conversion works. int("12") works because "12" is digits all the way through. int("twelve") fails -- Python can't turn the word "twelve" into a number, so it raises a ValueError. Before running a conversion, you can predict which outcome you'll get just by looking at the value: is every character actually a digit (and at most one decimal point, for a float)? If yes, the conversion is valid. If there's a letter, a stray symbol, or anything that isn't part of a number, it's invalid.

The Troubleshooting Routine

Type bugs are often silent -- the program runs without crashing, but does the wrong thing anyway. That's actually harder to catch than a crash, so type bugs get their own routine:

1Read the message. If Python crashed, what does the error actually say? If it didn't crash, what did it print instead of what you expected?
2Identify the values involved. Which variables are part of the broken line?
3Check the types. Add a print(type(...)) for each value in question. Don't guess -- check.
4Test a conversion. Try wrapping the value in str(), int(), or float(), whichever matches what the value needs to become.
5Revise based on the result. Did that fix it? If not, go back to step 3 -- there may be more than one value with the wrong type.
6Ask a specific question if needed. Not "it's not working," but "I expected X, I got Y, here's what type() showed me."

Worked Example

Here's a real broken program. Read it before scrolling to the explanation.

# rating is supposed to be a whole number
rating = (input("Enter a rating between 1 and 5"))
points = (rating) * 100
print("You have " + (points) + " to start.")

Run this and type 3 when asked. It does not crash. It prints:

You have 333333333333333333333333333333... to start.

That's step 1 of the routine already telling you something: no error message, but clearly not what was intended. input() always returns a string, so rating is the string "3", not the number 3. "3" * 100 is completely valid Python -- it means "repeat this string 100 times" -- which is why nothing crashes. The fix (step 4): convert rating to an integer right after reading it, with int(rating), so the multiplication is real math instead of string repetition. The print() line then needs its own fix too, since points is now a number and can't be joined with + directly to text -- wrap it in str(points).
