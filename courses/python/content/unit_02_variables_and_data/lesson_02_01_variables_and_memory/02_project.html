2.1 Project Instructions: Character Status Tracker

A short applied task after Practice. This one asks you to build a small piece of a game's character state using variables, the same way a real game would track it behind the scenes.

The Task

Write a program that tracks a game character's status using variables, prints that status clearly, then updates one part of it partway through, the way a character's state changes during real play (taking damage, leveling up, picking something up).

What This Could Look Like

Here's the output a finished tracker might display when you run it, just to show the shape of what you're building. This isn't code to copy, and your own variable names, character, and event don't have to match this one at all.

Character: Nia
Class: Mage
Health: 100
Lives: 3
Health: 80

Hint 1: Start by listing, on paper or in a comment, what pieces of information your character actually needs (a name, a class, health, lives, whatever fits your idea). Each one becomes its own variable.

Hint 2: Create and print one variable at a time first. Get character = "Nia" and its print() line working before adding the next variable. Once every variable prints correctly, add the one line partway down that reassigns an existing variable (like health going down), and print it again to show the change.

Hint 3: A shape to fill in, not a solution. The variable names, values, and wording are yours to choose.

# Create your character's starting variables here


# Print each one with a clear label


# Something happens. Reassign one variable to a new value


# Print that variable again to show it changed

Checklist

Required
  • At least 4 variables describing your character's state (for example: name, class, health, lives). At least one is text (a string) and at least one is a number.
  • Each variable printed with a clear label, the way this lesson's Practice items did (print("Health:", health), not a bare number with no label).
  • At least one variable reassigned partway through the program to a new value, simulating something happening in the game, then printed again so the change is visible.
  • Every variable name follows the naming rules from this lesson (starts with a letter or underscore, no spaces, snake_case for multi-word names).
  • No syntax errors. Run it and fix anything Python flags.
Tier 1 Bonus (+10 XP)
  • Add at least 2 more state variables beyond the required 4, covering different kinds of information (not just more of the same thing).
  • Add a comment above at least one variable explaining why you named it the way you did.
Tier 2 Bonus (+20 XP, on top of Tier 1)
  • Reassign a second variable at a different point in the program (a second event), not just the one required reassignment.
  • Write a short comment (2-3 sentences) explaining, in your own words, how the labels you chose for your print() output would help an actual player understand what they're looking at.
Game Connection

This is a small, real version of what a game's save system or heads-up display actually does: hold a set of variables describing the current state, and update them as the player acts. Everything you're doing here scales up directly into real game code later in the course.
