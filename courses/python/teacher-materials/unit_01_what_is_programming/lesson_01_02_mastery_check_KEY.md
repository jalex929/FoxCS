# 01.2 Mastery Check: Teacher Key

**Never include this file in the folder distributed to students.**

**1. (DOK 2. Application to a new scenario)** Input: hands detected underneath the sensor. Process: deciding to turn the fan on/keep it on while hands are detected, turn it off when they're removed. Output: the fan running (air moving). Full credit requires input to be the *sensing event*, not "hands," and process to include the ongoing decision (fan stays on only while input continues). This is the one that most often gets flattened into "input = hands, output = air," skipping process entirely.

**2. (DOK 2. Explain a general principle using a specific case)** Looking for: process is internal/invisible by design. The user only experiences what goes in and what comes out, not the calculation/lookup/decision in between. Full credit needs a real example from the lesson (checkout scanner's price lookup, kiosk's guest-list check) as the illustration, not just a restatement of the definition.

**3. (DOK 3. Take and justify a position)** Expected strong answer: disagree, or agree-with-a-caveat. Output is what the user *notices*, but it's entirely dependent on the other two stages; broken input means the process has nothing correct to work with, and broken process means even correct input produces wrong output. Full credit requires reasoning through what breaks, not just asserting "they're all important." A well-argued "output actually is most important because X" answer that engages seriously with the counterargument can also earn full credit. This is a justify-your-stance item, not a single-right-answer item.

**Common misconception to watch for (`CODE-01`):** collapsing Process into either Input or Output. E.g. describing the checkout scanner as "Input: scan barcode, Output: price appears," with no separate Process step named at all. This is the core skill this mastery check is testing; if a student does this on more than one question, that's a real gap, not a wording issue.
