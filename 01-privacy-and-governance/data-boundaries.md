# Data Boundaries

## Principle: Privacy by Separation

Student identity lives in exactly one place: the private, teacher-controlled roster (see `codename-policy.md`). Every other system in FoxCS — Moodle, the grader, any AI-assisted feedback drafting, the spreadsheet dashboard — operates on codenames only.

## System-by-System Boundary

| System | Receives | Never receives |
|---|---|---|
| Moodle | Codename-based account, course content, submission tracking, approved feedback/grades | Real name tied to grading logic (display name can be a codename) |
| Grader / AI feedback drafting | Codename, submission files, rubric, test cases, codename-based history | Student name, ID, any email, guardian info |
| Similarity / proficiency-consistency analysis | Codename, code, prior codename-based submissions | Same as above |
| Spreadsheet dashboard | Both — see below | — |
| Google Classroom | Whatever Google Classroom itself requires for your district's account setup (out of scope for this system to change) | N/A — this is the one surface that may need real identity for district/account-management reasons; keep the roster mapping on your side, not inside grading artifacts |

The spreadsheet dashboard is a special case: it needs a **private roster tab** (codename ↔ real name ↔ email, teacher-only) and a **grading/results tab** (codename-only, safe to hand to any AI tool or share more broadly if ever needed). Never merge these into one sheet — see `06-data-and-spreadsheets/`.

## Release Gate

Nothing generated by AI (score, feedback, XP, next-step recommendation, guardian-update draft) reaches a student or guardian without explicit teacher approval. No exceptions, including for high-confidence grader results. This applies to every pipeline stage described in `05-grader/`.

## Retention

Not yet defined — how long grading files, submissions, and reports are retained is an open question (see `open-questions.md`). Needs a decision before real student data is involved, not after.

## Behavioral Telemetry (added 2026-08-08)

`02-authoring-system/telemetry-and-analytics.md` adds interaction-level tracking (theme choice, code-stepper speed changes, hints used, Core/Reinforce/Extend routing, page open/save timestamps) beyond what this doc originally anticipated. It's covered by the same boundaries above, not a separate category: it's embedded in the same submitted file that already goes through the codename-swap step before reaching `05-grader/` or any AI tool, so it never has a path that bypasses the Release Gate. Contains no identity information by construction. The richer behavioral detail is exactly the kind of thing worth confirming with the district data privacy officer alongside the existing SOPPA-compliance flag in `codename-policy.md`, since "how a student clicked through a lesson" is a different sensitivity category than "what code they wrote," even with identity removed.
