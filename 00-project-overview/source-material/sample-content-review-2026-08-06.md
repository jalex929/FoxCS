# Sample Content Review — 2026-08-06

Jay added `FoxCS/Sample Content/` — real prior-year teaching materials (project banks, a full Unit 1 packet, a grading-feedback spec, rubrics, exam, game-concept reference list) as source material ahead of this year's redesign. This doc is the preserved findings from a full read-through, kept alongside the other source docs in this folder. See `decisions-log.md`'s 2026-08-06 "Sample Content review" entry for what was decided as a result; this file is the raw research, not the decisions.

**Note:** `Sample Content/` itself is real, sometimes lightly-identifying prior classroom material (student examples, group codes) — treat with the same care as any other student-adjacent content per `01-privacy-and-governance/`. Two filenames contain non-ASCII punctuation (an em dash and a non-breaking hyphen) — worth using tab-completion or copy-paste rather than retyping those filenames.

## 1. The old navigation pattern (why it wasn't sustainable)

`Sample Content/previous lesson content/` shows exactly one lesson's (U1L3, "Exploring Data Types") full resource stack. For a single lesson, a student needed **at least 6 separate files/links**: a 46-slide video-companion deck, Guided Notes (fill-in-the-blank companion), Practice (11 tasks, 3 tiers), a standalone Mastery Rubric + Objectives doc, an Extension Activity, and a Mastery Check — plus at least 2 more referenced-but-not-included destinations ("Review + Retest," "Next Lesson") and a separate answer key covering two lessons at once. The slide deck's own navigation was a static "Where to?" diagram with no links — just labels telling the student to go find the next file themselves.

**The real cost:** the Learning Objective and Language Objective were copy-pasted verbatim across at least 4 of these documents, and the mastery rubric was duplicated across 2 — no single source of truth, so any edit meant hunting down and updating every copy. The `Unit Guide_ Python Basics SY26.pdf` confirms this same resource-stack-per-lesson pattern was the model for the *entire* 10-lesson unit, not just U1L3.

**Direct validation for FoxCS's current design:** the numbered-flat-file-per-lesson structure (`01_instruction.html` → `NN_feedback.html`, one lesson folder, no external links, objectives stated once) is a direct fix for exactly this problem — single-source objectives, no lookup sheet, no missing/broken destination links. Worth naming this explicitly to Jay as validation, not just abstractly "simpler."

## 2. Iteration on a concept — real precedent exists, but not Jay's specific example

The clearest, most structurally deliberate "revisit and build on it" pattern in the whole sample set is the **Climate Action App Design workbook**'s three-stage cycle: Tab 8 (rough sketch) → Tab 9 (peer feedback + reflection: *"What did you change about your original wireframes after receiving feedback?"*) → Tab 10 (a full reading on why professionals iterate, quoting *The Mom Test*, then asking students to reflect again). This is explicit, formal, and reflection-anchored at every stage.

The closest **Python-specific** precedent is **Wasteland Adventure → Wasteland 2.0: The Expansion Pack**, a real, scheduled, graded revisit (11 days apart in the real pacing: original due 12/15, expansion due 1/23). Students return to their *own* original code, at the *same tier they originally chose*, and the required upgrades are direct escalations of the same graded categories: backpack list → backpack with user input → backpack with a `while` loop (explicitly named as the upgrade path). A "Level Up Any Time" guide tells students directly: *"You do not need to restart your file. You just add new sections and improve what you already have."* A required "Bug Hunt + Improvement Notes" peer-review step forces looking back at the original code before extending it.

**Jay's specific example — teaching input, later revisiting to add a loop, first "guess a set number of times" then later "guess until correct" — does not exist anywhere in these files.** The Python Project Bank has both shapes as two separate, unconnected entries (#4 "Number Guessing Warm-Up," single guess; #16 "Guess the Creature," loop until correct), but nothing frames them as a deliberate same-file revisit sequence. **This is a new design to build, modeled on the Wasteland/Expansion-Pack shape, not something to port from existing material.**

## 3. Project banks — existing structure to build on

Three banks exist (Python: 21 entries, Unity: 17 entries, Web Dev: 27 entries across 3 sub-tracks), all sharing a tiered Starter⭐/Power-Up⭐⭐/Legendary⭐⭐⭐ format with escalating point values. Common fields per entry: **Project Prompt**, **What You'll Make**, **Core Skills You'll Practice**, **Creative Twist** (the same technical requirement reframed into a different theme — this is the existing student-choice mechanism), **Challenge Mode** (optional stretch goal). The Python bank additionally has **What You Need to Know First** (explicit GMetrix Domain/Lesson prerequisite links); the Unity bank has **Modules** (GMetrix Unity Certified User module range) and a **Suggested Tools** field; entries are self-contained and don't hard-reference specific lesson numbers. All three banks open with an explicit invitation to deviate: *"Feel free to put your own twist on any of these projects (or come up with your own project, using these for inspiration)."*

**Other student-choice precedent found:** the Unit 1 Exam offers two structurally different formats (a 5-question discrete exam vs. a long-form project, choice of 5 themes) graded against one shared rubric — a genuine "many paths, one skill check" model, directly matching what Jay described wanting. The Wasteland tier system lets students switch tiers mid-project without penalty or restart. Unity bank entry #16 ("Build-Your-Own Game Project") is the most fully-developed self-directed/scoping structure — students pitch their own concept and self-split it into Starter/Power-Up/Legendary features.

## 4. Rubrics — two real, contrasting examples

`Rubric_ Game Concept Project Presentation.pdf`: 7 categories × 6 levels (0-5), presentation/creative-quality focused, fairly generic parallel language per level ("No X presented" → "Exceptional X").

`U1L3 Mastery Rubric and Objectives.pdf`: a single holistic band (0 Not Evident → 5 Mastery) covering multiple skills at once per level, with concrete, checkable behavior per level rather than generic quality words (e.g., level 3: *"Most data types are identified correctly. type() is used correctly in most cases... Type conversion may be slightly incorrect."*) — meaningfully more diagnostic than the presentation rubric, and closer in spirit to `ai_autograder_feedback_guidance.md`'s "best-fit scoring" approach.

## 5. `ai_autograder_feedback_guidance.md` — already a near-complete grading spec

26 sections, ~1290 lines. This is the single most directly reusable file in the set for `05-grader/`. Highlights: a defined feedback voice (banned vs. preferred phrasing, second-person, evidence-only, no speculation about effort/motivation); an 8-step standard feedback pattern; explicit rubric-preservation rules ("primary source of truth," never substitute a generic system, best-fit scoring so one minor gap doesn't tank a score); a fixed mastery-check label set (Mastery Demonstrated / Nearly There / Needs Additional Practice / Not Enough Evidence / Teacher Review Required); an `essentialForMastery` concept for criteria that can block mastery even with a high overall score; a rare, capped (+2, requires teacher approval, never auto-applied) above-and-beyond bonus; a full JSON output schema (assignment/rubricResults/score/feedback/bonusRecommendation/review) that looks ready to use as `05-grader/`'s target output format; an Academic Integrity section that never accuses, only flags specific listed conditions for teacher review; a 14-item human-review-trigger list; 7 worked example feedback blocks covering common submission types (fully correct, partial, incorrect approach, blank, valid-alternative-solution, etc.). Explicitly states it governs *this* grading system, not the separate "Waypoint Learning application."

## 6. Unit structure and pacing (for reference)

`Unit Guide_ Python Basics SY26.pdf`: 10 real lessons (U1L1–U1L10) with real due dates, GMetrix-domain lessons interleaved (U1L4, U1L7, U1L10), the Wasteland project and its Expansion Pack scheduled 11 days apart. `[Template] Study Guide_ Unit 1 Python Basics.pdf`: a different artifact — a partner-based, 8-section, 4-tier (adds a "Mythic," noted as "chosen by your class!") collaborative exam-prep worksheet, not a graded assignment, ending in a self-assessment discussion of which concepts feel strong vs. need more practice.

`Game Concept Categories + Examples.pdf`: a 20-category reference list (Action-Adventure, Puzzle, Platformer, RPG, Simulation, Strategy, Sports, Horror, Exploration, Educational, Party/Mini-Games, Mystery, Survival, Sci-Fi, Fantasy, Historical, Artistic/Experimental, MOBA, Rhythm/Music, Card/Board), each with 3 commercial examples — this is the list students pick from at the start of the Game Studio Concept Project.

`Unit 1 Exam_ Python Basics (V2) SY26.pdf`: group-based, open-notes, AI-support explicitly allowed *with mandatory per-question AI-use documentation* (screenshot/chat-link or "No AI used"), graded on a shared 5-category 100-point rubric where AI Documentation is itself a 10-point category — a real, already-lived-with precedent for how Jay wants AI-assisted work handled, worth checking against `01-privacy-and-governance/academic-integrity-ai-use.md`'s current all-or-nothing "AI use = 0" policy, since the exam's actual practice is more nuanced (documented AI use is fine and graded; undocumented AI use earns no credit for that part).
