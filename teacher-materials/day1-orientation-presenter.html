Game Programming I

Everyone learns Python, the whole way through — no pathway choice here.
What This Course Actually Is

Not just a Python-syntax class — a game design class that happens to use Python as the tool for building things. Every unit connects the code to a real idea about how games work and how they're designed to feel a certain way to play.

By the end of the year: real, working programs and games built from scratch, and preparation for a real industry certification — IT Specialist – Python.

The MDA Framework

The lens used all year, starting today, before any real code: Mechanics (the rules) → Dynamics (what happens when players interact with those rules) → Aesthetics (how it feels to play).

Have them name an M/D/A for a game they already know — that's the whole idea.

Tools, Already Set Up

Python + VS Code — pre-installed, students just confirm it works. Get them saving constantly with Ctrl+S from day one; it's the habit that saves the most pain all year.

How Practice Works Here

Practice adjusts to what each student actually needs — nobody is ever told they're "behind" or on a lower track. The work you get is the work that helps you right now.

When Something Breaks

Troubleshooting is learning, not a sign something went wrong. Five-step process: understand it → plan → try the smallest version → check against what you expected → revise. Errors are information, not failure.

Getting Unstuck

Asking a classmate first is genuinely a good option — not a fallback, as long as they know how to ask well (specific question, what they already tried). Then the teacher.

Academic Integrity — Say This Directly

To start the year, we will not be using AI in our work. Not code, not written responses, no exceptions until explicitly stated otherwise for a specific assignment.

Partner work: both people actually work, or only the person who did the work gets credit. Helping a classmate means explaining how to think through it — never handing over your file to copy.

If the line gets crossed: a call/email home → a logged incident in Aspen leading to a conversation with the Disciplinary Team → a 0% that can't be made up. An honest, wrong attempt always earns more credit than a cheated "correct" one. That's the whole point of how this is set up — say that part out loud.

Day-1 Kickoff Activity

MakeCode Arcade avatar (short, fun, hands-on) + a one-slide self-introduction in their own Google Slides file. Good icebreaker while you're doing the logistics above with the room.

Game Programming II

Shares a room and period with Web Design II — the pathway choice below isn't tied to which class a student is enrolled in.
Say This First, To the Whole Room

"You're not split into two separate classes making two separate decisions. You're one room, and everyone here picks whichever pathway actually excites them — Web Dev or Game Design/Unity." A Game II student can choose Web Dev. A Web II student can choose Game Design/Unity. Frame it warm and exciting, not just as a rule.

Tools, Already Set Up

Both pathways' tools are pre-installed and already confirmed — Unity Hub for Game Design/Unity, VS Code + browser for Web Dev. Students haven't chosen yet, so both get confirmed before the choice is made.

Shared Foundation (Same as Game I)

Same non-R/C/E-labeled adaptive practice model, same troubleshooting-is-learning framing, same 5-step problem-solving process, same "ask a classmate first, then teacher" culture, same academic-integrity policy (no AI to start the year, partner-work rules, same consequence sequence).

The Pathway Choice
Game Design / Unity

Design and build real games in Unity using C# — mechanics, player experience, level design, moving from 2D into 3D partway through the year. Everyone starts with a few weeks of game-design basics and MakeCode Arcade before Unity itself, since Unity is new territory for almost everyone.

Web Dev

Real, usable websites and web apps with HTML, CSS, and JavaScript — design for a real person using what you build, test it, revise it. A student who already knows HTML/CSS well can move faster into JavaScript.

Certification Target

Unity Certified User Programmer — required. Every student gets the full progression toward this. Unity Certified User Artist — achievable, not guaranteed. Real opportunity to add it if class time is used well; frame this supportively and honestly, not as a threat — completion depends on how the time gets used, and the content won't wait.

Day-1 Kickoff Activity

Same as every FoxCS course: MakeCode Arcade avatar + a one-slide self-introduction in their own Google Slides file.
